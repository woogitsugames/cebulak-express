### Procedura wgrywania ZIP-a od GPT
1. Rozpakuj do **nowego, pustego katalogu tymczasowego** (dane niezaufane).
2. Obejrzyj arkusz podglądu i każdy PNG (Read): 1620×900 RGBA, przezroczystość, **gruby granatowy kontur A+** (płaskie bez konturu → odrzuć i dopisz do zlecenia poprawek), brak napisów/logo/flag/herbów. Id pliku musi istnieć w `src/content/waypoints.ts` lub `PL_CITIES` w `src/core/route.ts`.
3. Kwantyzacja panoram: **najpierw** Pillow `quantize(256, FASTOCTREE)` na RGBA (alfa < 16 → 0), **potem** `python3 tools/art/quantize-assets.py <pliki>` (już tylko oxipng). Samo `quantize-assets.py` (libimagequant + dithering) daje pliki 3× większe (~480 kB zamiast ~150 kB). Kopiuj do `public/assets/landmarks/<id>.png`.
4. `ASSETS-NN.md` dopisz na koniec `public/assets/landmarks/ASSETS.md` (+ notka koordynatora), podgląd do `docs/art/podglady/`.
5. `npm run art:postcards`, testy (sekcja 6), `public/licencje.html` regeneruje się w buildzie — commituj. Zaktualizuj tabelę w `docs/zlecenia/runda8/README.md`.

## 5. Środowisko (co zainstalować / gdzie co jest)
- `npm ci` (Node 22). Playwright **1.63.0** używa Chromium **build 1243**, który jest już w `/opt/pw-browsers` — **nie uruchamiaj `playwright install`**. WebKit lokalnie nie działa (sprawdza CI).
- Narzędzie kwantyzacji: `pip install imagequant pyoxipng` (Pillow jest).
- Do analizy zawieszeń: `gdb` jest w kontenerze (`gdb -p <pid> -batch -ex 'thread apply all bt 25'`).
- **APK:** lokalny Gradle pada na Maven 429 — bierz z CI: artefakt `cebulak-express-debug-apk` z workflow CI na PR/main. Lista: GitHub MCP `actions_list` → `list_workflow_run_artifacts`; pobranie: `curl -L -o apk.zip https://api.github.com/repos/woogitsugames/cebulak-express/actions/artifacts/<id>/zip` (repo publiczne, działa bez tokenu). Gdyby trzeba lokalnie: `ANDROID_HOME=/opt/android-sdk`, `android/local.properties` z `sdk.dir=/opt/android-sdk`.
- Trace/wideo z CI: artefakt `playwright-e2e` (ok. 200–400 MB) — rozpakuj tylko potrzebny katalog (`unzip a.zip "*fragment-nazwy*"`).
- **Port 4173:** Playwright ma `reuseExistingServer` — nie uruchamiaj testów równolegle z agentem w innym worktree i nie zostawiaj `vite preview` na 4173 (testy wezmą cudzy build). Własne podglądy stawiaj na innym porcie (np. 4174).

## 6. Jak sprawdzać (przed każdym PR)
```
npx tsc --noEmit && npx tsc --noEmit -p tsconfig.e2e.json && npx vitest run && npm run build
npx playwright test --project="Desktop 1280x800 (Chromium)" --project="Pixel 7 (Chromium)" --workers=2
for i in 1 2 3; do npx playwright test --project="Slow 4G + CPU 4x (Chromium)"; done
```
- Budżet pierwszej klatki (Slow 4G) < 2 s: nowe moduły ładuj dynamicznie, nie importuj ich w `src/main.ts`.
- Nie przebudowuj `dist` w trakcie testów Playwright.
